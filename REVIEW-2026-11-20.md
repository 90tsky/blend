# blend: interface review, 20 Nov 2026

Code in `src/`, `index.html` reviewed against two checklists: the **Web Interface Guidelines** (Vercel, copy downloaded 20 Nov) and **better-typography**. The house rules (`.claude/design/`) and DESIGN.md came first: where a guideline clashed with them, the house rule won (for example sentence case, not the guidelines' Title Case).

All changes are unsaved changes in the working copy. Nothing was committed, pushed or deployed. `CASE-STUDY-NOTES.md` and `NEXT-SESSION.md` were not touched (their changes are from earlier work).

**In short:** the code was already in good shape. Typography in the UI strings was clean (curly quotes, single-character ellipsis, "·"), icon buttons were named, toasts were live regions, and dialogs trapped focus and closed with Esc. The real problems were all keyboard ones: focus hidden behind fixed bars, focus rings cut off by scrolling rows, and one radio group with no arrow keys.

## 3. What I checked that already passes
- Zoom isn't blocked; there's no `transition: all`; there are no click handlers on `div`s except the Size guide dim, which also has Esc and ✕.
- All icon-only buttons are named. Decorative icons are `aria-hidden`. Toasts and the "Saved to your photos" pop-up use `role="status"`. The "3 of 7" line and the filter count are announced.
- Dialogs (Search, Size guide, Try-On) use `aria-modal`, close with Esc, make the page behind inert, and return focus to the button that opened them.
- Pickers are radio groups with arrow keys and a single Tab stop.
- Reduced motion: the CSS kill switch plus `MotionConfig reducedMotion="user"`. The badge pop and Checkout slide (`useAnimate`) were tested and respect it.
- `color-scheme`; `theme-color` follows the Appearance setting (store.tsx:204); safe-area insets; `overscroll-behavior: contain` on sheets.
- Inputs are 16px, so iOS won't zoom. The loaded font weights (400–700) match every weight used, and nothing is faux bold or faux italic.
- All UI strings already used ’ “ ” … and "·". Prices use `toLocaleString` with a comma for thousands, as decided.
- Images below the fold are lazy-loaded and the first banner is `fetchpriority="high"`. Most `<img>` have width and height.
- No console errors or warnings in any screen, light or dark, phone or laptop, before or after. (The only messages were Motion's own notice that reduced motion was on, during that test.)
